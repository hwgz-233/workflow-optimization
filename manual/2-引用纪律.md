# §2 引用纪律

> 适用：任何"把某个结论写进文档"或"拿某个数字做判断"的场合
> 依据原理：**§1-11 对账以证据为准**、**§1-8 指针必须可执行**、**§1-9 对账同源**

---

## 2.0 为什么需要这一节

一次真实事故：

一份指南要求把旧的 `A / B` 两个参数值标为「**已作废**」，
改用「**某次复核得出的** `C / D`」。而**那次复核本身是错的** ——
`A / B` 本来就是对的，`C / D` 把容量压低了 24–39%。

**如果照做，指南会成为错误值的放大器** —— 而那个错值，正是**靠文档扩散到 11 处**的。

**根因不是"某个人粗心"**，而是引用时**少了一道纪律**。这一节就是补这道纪律。

### 这一次事故教会我们的三件事（2026-09-28 补）

1. **错值的传播力比正确值强。** `C / D` 只被"记"过一次，却被抄进 11 处；
   `A / B` 虽然一直是对的，但没有任何机制为它背书。⇒ **纪律要作用在"抄"这个动作上**。
2. **判定类参数"只留指针"救了场。** 因为唯一实现是代码，纠错**只需改一处代码**
   ——**这是单一数据源在真实事故里的价值证明**。
3. **但"只留指针"当时没定粒度**，差点把"旧值"换成"空话"。⇒ 见 2.3 的**可执行指针**三件套。

## 2.1 唯一原则：权威判据是「证据支持」，不是「来源身份」

**来源的身份属性与正确性无关。** 以下全部是**无效判据**：

| ❌ 无效判据 | 典型表述 | 为什么无效 | 实测案例 |
|---|---|---|---|
| **新** | 「这是最近一次复核 / 修正的结论」 | **复核本身可能是错的** | 那份把容量压低 24–39% 的"校正值"，就是一次"复核"的产物 |
| **活** | 「以正在生效 / 被使用的那份为准」 | **在用的可能正是被淘汰的版本** | 自动加载的活数据记的是**被淘汰的 v1**；旧支线记的才是已交付的 v2 |
| **大** | 「这份文件更大、内容更全」 | 体量只说明"有差异"，**不说明差在哪一侧** | 24 KB 的旧支线 vs 14 KB 的活数据，两边**各有 3 块独有内容** |
| **自称** | 「这是权威文档 / 唯一数据源」 | 自称不是证据 | `README` 自称某目录是"人类可读副本"，实际是**双向发散的废弃支线** |
| **来源** | 「专家说的 / 手册写的」 | 手册同样会错，**本手册也不例外** | 本手册的 §2 就是在一次错值事故之后才写的 |
| **重复** | 「很多地方都这么写」 | **多副本 ≠ 多证据**，可能全部同源出错 | 错值扩散到 11 处，11 处**不能互相作证** |

✅ **唯一有效判据**：能被 **命令与输出** ／ **原始文件** ／ **多个相互独立来源** 支持的，才算权威。

### 两条判据（可直接用）

- **身份判据自检**：当你想说"因为它是 X，所以它对"——停。**X 是来源的属性，不是证据。**
- **反向验证**：如果同一个来源在另一件事上是错的，你还认为它在这件事上自动正确吗？

### 🔴 裁定冲突时，必须**做实物验证**（2026-09-28 补）

**不要在两份文档之间比"谁更新 / 谁更活"，要问"谁能被实物证明"。**

| 可用的实物证据 | 例 |
|---|---|
| **跑一次真实产物的输出** | `ffmpeg -i 成品.mp4` → `Duration: 00:26:23` |
| **构建产物本身** | 45 份图片产物落盘、页面数据 45 条 |
| **独立的一次性交付记录** | 该次合成记录写明「成品版本：v2（45 页 / 26:23）← 当前交付版」 |

⚠ **三条独立证据一致时才算硬结论**；只有一条、或三条其实同源（如都抄自同一份文档）时，
**降级为待验证项**。

## 2.2 证据三级

| 级 | 类型 | 要求 | 能否作判定依据 |
|---|---|---|---|
| **①** | **实测** | 附**命令**与**输出**（可复现） | ✅ 可以 |
| **②** | **校准推算** | 附**模型**与**误差范围** | ⚠️ 仅用于规划，**不得用于合格判定** |
| **③** | **推断 / 转述 / 印象** | 必须**显式标注为 ③** | ❌ 不可以 |

> **来源说明**：本节的三级分类**不是本手册发明的**，是转述某个长周期项目在实战中总结的
> "数字三分类"。按 2.4 的纪律，**转述本身就该被标注** —— 这里标注了。

### 🔴 ① 级的额外进场条件（2026-09-28 补）

拿到一个"实测结论"时，还要过两道闸：

| 闸 | 问句 | 反面案例 |
|---|---|---|
| **同源性** | 这个数和我拿来比的另一个数，**是同一次执行产生的吗**？ | 拿旧成片时长比新计划名义和，虚构出"合成端有 bug" |
| **自洽性** | 这个结论**和它自己的输出打架吗**？ | 脚本输出写着"100 字 → 10 行"，脚本前提却写"每行 12 字" —— 自相矛盾还产出了"校正值" |

> **看到超预期的差异，先怀疑数据源，再怀疑逻辑。**
> **结论与自己刚打印的数据对不上时，先信数据。**

### ③ 级的处理方式

③ 级不是"不许用"，而是**不许当依据**：

- 可以写成「**待验证项**」，并注明**由谁、在什么条件下**能把它升到 ①
- 不得写进"判定标准""合格线""应当改为…"这类结论性位置

## 2.3 🔴 可执行指针（判定类参数写法的硬要求）

**"只留指针"如果只写"以代码为准"，等于把文档里的旧值换成了文档里的空话。**

**凡判定类参数（参与合格判定的），文档里必须写成三件套：**

```
① 唯一实现是什么：  layout_check.py 的 pair_limit()
② 怎么自己查到：    跑 preflight.py --no N，会逐页报当前上限
③ 错了会怎样：      渲染器在渲染前硬失败，一张图都不写
```

- **判据**：见 **§1-8**（本节不重复，避免造第二处正文）。
- **反例**：「本参数以代码为准，本文不复制数值。」 —— 读者仍然不知道该去哪看。

### 附：判定类 vs 参考类的**判据**（2026-09-28 补）

原决议只给了例子，没给判据，实操里模糊项比预想多。**用这条：**

> **脚本能自动判的 ＝ 判定类（只留指针）；只能靠人眼看的 ＝ 参考类（可留副本）。**

| 项 | 脚本判不判 | 归类 |
|---|---|---|
| 图片尺寸 `1080×1440` | 脚本判 | **判定类** → 只留指针 |
| 页脚坐标 `y=1300` | 脚本**不判**（要人放大看） | **参考类** → 可留副本 |

## 2.4 🔴 引用格式（这是防错载体，不是建议）

**凡写下「新值 / 校正值 / 更正为 / 以某一版为准」，必须填满这个模板：**

```
结论：
证据等级：① / ② / ③
证据：        ← ①填命令＋输出；②填模型＋误差；③填来源
原值：
变更理由：
已回填位置：  ← 改完逐一勾选，见 §4-10
```

**🔴 填不出「证据」这一栏，就不许把这句写进去。**

**为什么用模板而不是"多提醒一遍"**：

- 重复提醒 → 该忘还是忘（**提醒靠注意力，注意力会失效**）
- 必填栏 → **漏填比填错更容易被自己发现**
- 这是**防错（Poka-Yoke）**：不是提醒你两次，是**让你写不出来**

> ⚠️ **诚实标注这条的验证状态**：
> 实战中**真正挡住错值的，是"判定类只留指针"这个结构，不是这个模板** ——
> 因为当时这个模板还不存在。**所以这条属于"设计合理但尚未被实战检验"。**
> **不把它写成"已验证"。**

## 2.5 禁止的引用方式（反例类型）

| # | 反例类型 | 为什么错 | 正确做法 |
|---|---|---|---|
| 1 | 「某次复核已校正为 X」（无命令无输出） | 未经验证的复核＝③级 | 补实测；补不上就标 ③ 并列为待验证 |
| 2 | 「以正在生效的那份为准」 | 身份判据；在用的可能就是错的 | 逐项找证据，**"活着"不是判据**；必要时做实物验证 |
| 3 | 「这份更大 / 更新，所以更全」 | 体量与时间都不是证据 | 做**集合级比对**（按章节/字段），别按体量推 |
| 4 | 「多处文档都这么写」 | 多副本可能同源出错 | 追溯最初来源，验它的证据 |
| 5 | 「先按这个改，回头再验」 | 会立刻扩散成新副本 | 验完再改；或改动**只落单一源头**，待验部分显式标注 |
| **6** | 「**按"值"搜一下就能确认**」（当搜索本身是判据时） | **搜的边界**：搜只能判"**有没有标注**"，**判不了"值对不对"** —— 一个**当前正确**的值在多份文档里各写一遍也会被标红 | 搜索**只用于找副本**；**"该不该改"必须人对照权威值（实测）判断** |
| **7** | 「**全项目搜 X，命中为 0**」当作验收 | 与"历史留档可以保留"**互斥**，人工判不了、机器也判不了 | 改**两栏制**（清零范围 / 允许留存范围）＋**带排除的命令**，见 §4-3 |
| **8** | 「**这是新旧同源**：文档、脚本、注记都这么说」 | **多副本 ≠ 多来源** —— 若三者都抄自同一份没有证据的文本，它们**只能算一份** | 检查它们的**共同祖先**；只认能追溯到**命令与输出**的那一条 |

## 2.6 权威冲突时的判定流程

```
① 把冲突项逐条列出        ← 不要合并成一条，合并会掩盖"只差其中一项"
② 每项各自找硬证据         ← 优先级：命令输出 > 原始产物 > 相互独立的多个来源
③ 做实物验证              ← 跑一次真实产物，不要比"谁更新/谁更活"
④ 有证据的一方胜出；三条独立证据一致才算硬结论
⑤ 双方都无证据 → 标「未决」，列入待验证项，不得任选一方
⑥ 胜出后：改全所有引用点（§4-10），并留下变更记录
```

**⚠ 第 ⑤ 步是这一节的例外**：确实是 ⑥ 步的先决条件。**"未决"是合法结论，"任选一个"不是。**

## 2.7 自检清单（写完任何含数值/结论的文档后逐条勾）

- [ ] 文中每个数字/参数/结论，我能说出它是 **① / ② / ③** 哪一级吗？
- [ ] **③ 级的，是否已显式标注，且没有被放在判定标准的位置？**
- [ ] 有没有"因为 X 是新的 / 活的 / 大的 / 权威的，所以 X 对"这类表述？
- [ ] **拿来做判断的 ① 级证据，与我拿来比对的另一个数，是同一次执行产生的吗？**
- [ ] **我的结论，与我手上数据的输出/打印，有互相矛盾的地方吗？**
- [ ] 所有变更类结论，是否**填满了 2.4 的模板**（尤其"证据"与"已回填位置"两栏）？
- [ ] 冲突项是**逐条列出**的，还是被合并处理了？
- [ ] 我引用的"事实"，**原始出处在哪**？我能指出文件与位置吗？
- [ ] 判定类参数，我写的是**可执行指针（三件套）**，还是"以代码为准"这类空话？
- [ ] 我有没有把"搜索结果"当成了"正确性证据"？

## 2.8 一句话

> **来源的身份（新 / 活 / 大 / 权威）都不是证据。**
> **能被命令与输出支持的，才是。**
> **填不出证据，就不要往下写。**
> **有分歧时，跑一次真的，别比谁更新。**
