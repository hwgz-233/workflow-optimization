# §4 规范编写纪律

> 适用：任何"写给别人（或别的会话）照着执行"的规范、指南、清单、SOP
> 依据原理：§1-1 ~ §1-13（尤其 **§1-5 未执行≠通过**、**§1-12 验收要判到要考的东西**、**§1-13 规则要写明奖励什么行为**）

---

## 4.0 为什么需要这一节

一次真实改造中，**同一份指南被三个不同的执行方独立挑出同类缺陷**。

这说明问题不在某一处疏漏，而在**"把原则落成可执行条目"这一步缺纪律**。

**核心事实：知道原理 ≠ 写得出可被正确执行的规范。**

最常见的失手方式甚至不是"写错"，而是**"写对了原理、却给了执行方一个会误解的形状"** ——
例如：给了目标没给判据、给了检查没给例外出口、给了清单没给依赖顺序。
**这类缺陷不会在执行前暴露，只会在执行后以"返工"或"假绿灯"的形式出现。**

### 🔴 定稿时补的第 12 条教训（2026-09-28）

> **这份指南防住了被改造对象的病，它自己的病还有 3 条没治好** ——
> **四份手抄本、修订只落一份、通则三处各写**，这三条是**同一个根因**。
> 而它们恰好是 §4-8 和 §4-10 要治的病 —— **指南要求别人做的，它自己没做到。**
>
> ⇒ **规范作者必须把自己也当作被检查对象。** 这一节的自检清单（4.2）
> **第一位读者是写这份规范的人自己**。

## 4.1 十二条编写要求

> 格式：**要求 → 判据 → 反例**。「判据」是可机械核对的问句，用来判断这条有没有做到。

### 1. 每个动作必须**可机判** —— 给判据，不给目标

- **判据**：把这条交给两个不同的人，他们会做出**一致的**判断吗？
- **反例**：「判定类参数只留指针」 → 哪些算判定类？没定义，两人必然分得不一致
- **正例**：「**脚本能自动判的 ＝ 判定类；只能靠人眼看的 ＝ 参考类**」
- ⚠ **判断力是稀缺资源，规范不该依赖它。**
- 🔴 **补充（2026-09-28）**：**字段本身也要有口径。**
  - 实测：「台阶」这一列**从来没人定义它描述什么** —— 4 条任务都填 `1`，
    但执行它们的通道**已经是 skill（台阶 2）**。
    于是汇总表里"已升级 = 1"**是靠解释推出来的，不是靠字段读出来的**。
    **同一份数据，换个解释就能得出不同的候选名单。**
  - **判据**：**这个字段的每一个可能取值，都有"怎么填"的说明吗？** 没有就别放进模板。
  - **处理**：拆成两列（`任务台阶` ＋ `执行通道`）比"一列两种解释"更可靠。
- **证伪**：把这条交给两个人，他们**做出了不一致的判断**（或某个字段的取值**没有填写说明**）→ 该条被违反。

### 2. 检查项必须定义「**未执行**」与「**合法跳过**」两种语义

- **为什么**：不定义，就会造出**新的假绿灯** —— 没输入也算通过。
- **判据**：见 **§1-5**（该条已升格为原理，本节不重复）。
- **要求**：显式区分三种结果 ——

  | 状态 | 含义 | 对总判定 |
  |---|---|---|
  | `通过` | 真跑了且合规 | ✅ |
  | `失败` | 真跑了且不合规 | ❌ |
  | **`未执行`** | **缺输入 / 物理上跑不了** | **不得 ✅，降级并自述覆盖面** |
  | **`知情跳过`** | **显式声明不做**（`--skip-xxx`） | 允许 ✅，**预期项数同步下调** |

  **`未执行` 与 `知情跳过` 都不得计入通过数。**
- **反例（两个项目各犯一次，形态不同）**：
  1. 8 项预检里 **① 四边越界、② 块内溢出在未渲染时物理上跑不了**；**⑧ 残留词在没给特征词时无意义**。
     为凑够 8 项硬跑 → 无意义结论；静默算通过 → **绿灯判的是另一件事**。
  2. 用词一致性检查「**没给对照表就当这一项通过**」 → 总判定照样 ✅。
     ⚠ **项数校验恰好堵不住它**（项数是对的，只是那一项没真跑）。
- ⚠ 这与原理「绿灯判的是另一件事」同源 —— **修假绿灯的动作本身，最容易造出新的假绿灯。**
- **证伪**：某个检查项**没输入 / 没真跑，却计入了通过数**（总判定照样 ✅）→ 该条被违反。

### 3. 验收标准必须**可达成 + 不自指矛盾 + 可机判**

- **判据**：验收条件与本文档的其他要求，**能同时成立吗**？**机器判得了吗**？
- **反例（实测，同一形态两个项目各犯一次）**：
  - 「全项目搜 X，**命中为 0**」—— 而同一份文档的另一条要求"保留含 X 的历史记录留档"。
  - 「命中只剩带'已作废'标注的历史记录」—— 需要人逐条对照文件名判断，**不可机判**。
- **要求：负向验收一律用「两栏制」，并给出命令**：

  ```
  清零范围：  活文档（README / 规范 / SKILL / 进度 / 设计稿）
  允许留存：  日期日记 · 指南/评审原文 · 带「旧值/已作废」标注的历史段落 · 归档目录
  ```

  ```bash
  grep -rn "旧值" --include="*.md" . \
    | grep -v "旧版归档\|迁移记录\|改造指南\|memory"
  ```

- **要求**：验收写完后，逐条与全文其他要求对撞一遍。
- **证伪**：某条验收与本文档另一条要求**不能同时成立**，或它**机器判不了** → 该条被违反。

### 4. 改动项之间必须给**依赖顺序** —— 且要检查是不是**耦合**

- **为什么**：清单式罗列会掩盖"A 依赖 B 先完成"，执行方会按清单顺序做，然后卡住。
- **判据**：任取两条，**能说出"谁先谁后"吗**？说不出的，要么标注"无序"，要么补信息。
- **反例（顺序写反了）**：
  - 「先建 skill」与「先拆文档」并列 —— 实际后者要先做（否则新建的 skill 会立刻与旧文档形成双源）。
  - 「先做 A，再做 B」—— 但 A 的收尾动作要求"在原处改指针"，
    而**落点由 B 创建** ⇒ **按字面顺序执行会在中间态卡住**。
    实际执行序是：**A 建主体 → B 建落点并分配内容 → 回头做 A 的指针化**。
- ⚠ **"耦合"比"顺序"更常见**：不是 A 先 B 后，而是**A 做一半 → B → A 收尾**。
- **附加**：有依赖的，要写**"不按序做会怎样"**（那是最容易被忽略的信息）。
- **证伪**：按清单字面顺序执行，**在中间态卡住**（或任取两条说不清谁先谁后、也没标"无序"）→ 该条被违反。

### 5. 必须写「**在哪一步失败**」

- **为什么**：只说"升级为硬失败"不够 —— **失败点决定了会不会留下半成品**。
- **判据**：失败点上，磁盘 / 工作区里**是否有需要清理的中间产物**？
- **要求**：指明失败发生在**生成前 / 生成中 / 生成后**，并说明**中途失败怎么收场**。
- 🔴 **硬失败要在产生任何产物之前，且要一次报全部**（2026-09-28 补）：
  - 做法：`validate()` **先全量校验** → 命中就**一个产物都不写 + `exit 1` + 落 `_FATAL.txt`**
  - 好处：**不产出错误成品**；**一次列出全部问题**（不必改一个跑一次）
- **反例**：
  - 「放不下就报错退出」—— 但此时已渲染了一半图片。
  - 边渲染边失败 → 留下**改了一半的画面目录**，**残留的旧图可能被下游误用**
    （有过"**画面新、声音旧**"的同类事故）。
- **证伪**：失败点上**留下了需要清理的中间产物**（或报一条、改一次、再跑一次）→ 该条被违反。

### 6. 必须有**回归检查**（改完验"没坏"）

- **为什么**：只验"目标达成了"不够，还要验"原本好的地方没被改坏"。
- **判据**：改动清单里，**有没有一条是"确认 X 仍然正常"**？
- 🔴 **判据还要更进一步（2026-09-28 补）：这条回归检查必须"可复验"，不能是自我声明。**
  - **反例**：「没有把原本正确的地方改坏」**无法证伪**，等于没写。
  - **正例**：「**下次开工能走完第 0–1 步（读计划 → 找到第一项 → 读规范 → 读样例），
    并一句话说出下一项，不需要问人**」——可复验。
- **正例**：改造时明确列出"评审认定的三处做得好 —— 一处没碰"，并保留原样为验收项。
- **证伪**：回归项是**"没有改坏原本正确的地方"这类无法证伪的自我声明** → 该条被违反。

### 7. 检查项要有**假阳性出口**，且**豁免必须留痕**

- **为什么**：误报会训练人**忽略告警** —— 比没有检查更糟。
- **判据**：扫描类检查，**是否给了"确认合规后放行"的机制**？
- **反例**：残留词扫描命中规范文档里的"禁用词表"本身 → 每次都要人工排除，久了就无视告警。
- **要求**：提供标注方式（如 `--allow 词@位置`）或排除规则；
  **且"用户已同意保留的例外"必须显式写出来**（逼它留下痕迹）——
  **否则豁免本身成了新的静默失败。**
- 🔴 **半自动检查要明说自己是半自动的**（2026-09-28 补）：
  - 实测：同一类扫描有**两个必然误报源** ——
    ① 脚本 docstring 里的"规则说明"式反例词（`.py` 可排除注释与 docstring）
    ② **`.md` 规范/模板里的禁用词表**（`.md` 里**没法自动区分"规则说明"与"实际文案"**）
  - **规范要提前列出这两类"正常命中"**，并写明："**这个检查是半自动的 —— 它负责穷举，人负责分类**"。
- **证伪**：扫描类检查的**误报只能人工排除且无出口**，或**豁免静默生效不留痕** → 该条被违反。

### 8. 不许「多处写同一段文字」—— 只许**引用**

- **为什么**：要求"在三个地方各写同一段" ＝ **自己制造副本**，一旦只改一处必然漂移（已实测）。
- **判据**：同一段文字在文档里**出现几次**？> 1 就该改。
- **写法**：「本项以 `<唯一位置>` 为准」，别处只写指针。
- **⚠ 特别注意**：**"为了统一，在 N 处各写同一段"是自相矛盾的** —— 统一的唯一实现方式是**只写一份**。
- 🔴 **实测（2026-09-28）**：这句要求**真的漂了，一天之内漂了 1/3**：

  | 位置 | 状态 |
  |---|---|
  | 项目甲 | ✅ 逐字同文 |
  | 项目乙 `README.md` | ❌ 不同文：缺"原理：/通则："标签、把"（ffmpeg）"塞进了共用句 |
  | **本份指南自己的通则文本** | ❌ 写的"解释器 / 编码 / 环境变量"，而**母版写的是"…/ 外部依赖（ffmpeg 等）"** |

- 🔴 **分发形态的硬要求**（2026-09-28 补）：
  通用段（原理 / 铁律 / 自检清单）**只留母版为正文**，项目版只留
  "行号快照 + 本项目特有上下文 + 指针"。
  **若为保证执行方能自包含而必须复制全文，至少在副本头部写一句「本文件是母版 §X 的裁剪版，裁掉了什么」。**
  - 实测代价：母版自检清单 **8 条 → 项目版 6 条**，**裁掉的两条里有一条**
    恰好是「新增的检查项，写了它覆盖什么、不覆盖什么」——
    **而这一轮的执行盲点正好在这里**（把最值钱的一类任务排除在外，
    **没有一条自检项逼执行方写清边界**）。**若这条没被裁掉，第一步就会被告知。**
- **证伪**：同一段文字在文档里**出现 > 1 次**（即使当时逐字相同）→ 该条被违反。

### 9. 引用任何"新值 / 校正值"必须附**实测证据**

- **判据**：这条结论的证据等级是 **①（实测，附命令与输出）** 吗？（见 §2.2）
- **反例**：「经复核，正确值为 X」（无命令无输出）→ 若那次复核是错的，**规范会成为错误值的放大器**
- **要求**：未经验证的"复核值"**不得进入规范**；引用格式见 §2.4 模板。
- **证伪**：规范里出现**无实测证据的"新值 / 校正值"**（证据栏填不出却仍写进去）→ 该条被违反。

### 10. 分发出去的规范必须**有单一源头**，并给「怎么找副本」的方法

- **为什么**：同一份规范分发到 N 处 → 修订只落一处就漂移（已实测）。
- **判据**：修订一条后，**能列出"需要同步的全部位置"吗**？
- **两条硬要求**：
  - 在文档头声明**唯一源头**（"以 X 为准，本文件是副本 / 或本文即源头"）
  - 附**找副本的判据／命令**
- 🔴 **只教"要改全"不够，必须教"怎么把副本找出来"** —— 找不到就不可能改全。
- 🔴 **而且"找副本"不能靠已知路径，要靠"按值搜"**（2026-09-28 补）：
  - 实测：指南写"skill 本体与工作间副本是**两份**" → 实际 **3 份**，
    多出的一份**不在任何人的认知里**，藏着**已作废的判定值**。
  - **怎么漏的**：见 **§1-2** 的"副本数必须实测"（本节不重复）。
  - **正确做法**：**按值全仓搜** + 按**文件性质**分类（权威/代码 · 活文档 · 归档 · 日记 · 指南），
    **只挑出"未标注的现在时声明"**。
  - ⚠ **搜的边界**：它判"有没有标注"，**不判"值对不对"** ——
    **"该不该改"必须人对照权威值判断**。
- **证伪**：修订一条后**列不出需要同步的全部位置**（或副本数按已知路径推断、与实测不符）→ 该条被违反。

### 11. 验收线必须**判到要考的东西**，并给采集缺失率上限

- **为什么**：**一条只要求"能算出来"的验收线，采集动作缺不缺失，它永远不报错。**
- **判据**：**这个绿灯，判的是"我想考的那件事"吗？**（＝ §1-4 的问句，用在验收线上）
- **反例（实测）**：验收要求"能给出各类型耗时占比，并指认最耗时的那一类" →
  执行方**确实给出了**（76% / 24%），也**确实指认了** → **照字面算通过**。
  **但数字全是 AI 侧的**，而基准（"某个手工环节 ≈ 10 分钟"）**恰恰指的是用户侧**，
  那一栏 **4/4 条全是 `未测`**。⇒ **台账答不了它自己存在的那个问题。**
- **要求**：
  1. 凡"能给出 X"的验收，补上 **X 的采集缺失率上限**（例：「'用户侧耗时'的缺失率 < 50%」）；
  2. 凡"关键数据没人采集"，验收线**必须失败**，而不是"通过了但数据是空的"。
- ⚠ **配套**：光设阈值不够，还要给**采集落点**（见下条）——否则阈值只会逼出编造的数据。
- **证伪**：出现"**验收通过但关键数据全缺失**"，或验收线只要求"能算出来"而无缺失率上限 → 该条被违反。

### 12. 写明「**谁在什么时候采集**」，以及该规则的**口径**

- **为什么**：数据缺口的原因**通常不是"没意愿"，而是"没有落点"**。
- **判据**：见 **§1-6**（本节不重复）。
- **反例（实测）**：耗时缺的不是"记的意愿"，是**"谁在什么时候采集"没有落点**。
  解法：找到**已有的动作**做落点 ——「**他本来就要贴运行结果，只要多说 6 个字**」，
  写进那个动作的收尾条款里。**补了落点之后才有数据。**
- **要求**：
  - 采集点**借用已有动作**，不新开环节；
  - 明确**拿不到时写 `未测`，宁可空着不要编**；
  - 明确 `未测` 的行**不计入合计**，但要在备注里说明；
  - 🔴 **口径要单一明确，且细分行与合计行的算术关系要写明**：
    - 反例：要求"三行细分"，又要求"合计按端到端" ——
      而**用户真正花时间的那一步没有被任何一行承载** ⇒ **三行之和 ≠ 合计**，
      **表里会出现一个没有名字的差额**；
    - 解法：**把那一行明确写进模板**，或声明"**合计允许 > 各行之和，差额 ＝ 用户的时间**"。
      **否则每个执行方会各自拍一个口径。**
- ⚠ **还要写明这条规则在鼓励什么**（见 §1-13）：
  - 反例：为练习册加"未填写状态必须退出码 0"（本意：别崩）→
    **把参考答案全填进去恰好最容易通过它** —— 规则把执行方推向了它的反面。
- **证伪**：某个要采集的字段**没人写"谁在什么时候采集"**（或口径混用、细分行与合计对不上）→ 该条被违反。

## 4.2 规范自检清单（发布前逐条勾）

> 🔴 **第一位读者是写这份规范的人自己。**

- [ ] 每个动作都有**可机判的判据**（换个人也能做出一致判断）
- [ ] **每个字段的每个取值都有"怎么填"的说明**（没有就别放进模板）
- [ ] 每个检查项都区分了 `通过 / 失败 / 未执行 / 知情跳过`，且**后两种都不计入通过数**
- [ ] 验收条件**可达成、可机判**，且与全文其他要求互不冲突
- [ ] **负向验收用了两栏制（清零范围 / 允许留存范围）并给了命令**
- [ ] 改动项之间的**依赖（含"耦合"）已写明**，并标注了"不按序做会怎样"
- [ ] 每处"失败点"已指明，且**硬失败发生在产生任何产物之前、一次报全部**
- [ ] 至少有一条**可复验的回归检查**（不是"没有改坏"这类无法证伪的自我声明）
- [ ] 扫描类检查有**假阳性出口**，**豁免已留痕**，且**明说了这是半自动检查**
- [ ] 全文**无"多处写同一段"**，只有引用；**若必须复制全文，副本头部写明了"裁掉了什么"**
- [ ] 所有"新值 / 校正值"都有**实测证据**（或已降级标注为 ③）
- [ ] 已声明**唯一源头**，并给出"**按值搜**"的判据或命令
- [ ] **验收线判的是要考的东西**，且**关键数据的采集缺失率有上限**
- [ ] **每个要采集的字段都写了"谁在什么时候采集"**，并给了 `未测` 的记法
- [ ] **每条规则都问过"它奖励什么行为"**，且通过路径与设计意图一致

## 4.3 依据来源

本节十二条**不是推演出来的，是从真实缺陷归的纳**。

素材：**一轮改造中产生的 4 份独立反馈**（三份执行反馈 + 一份完成报告），
共 **25 条问题**，归并后落入以下类别 ——

| 归并后的类别 | 对应本条 |
|---|---|
| 给了目标没给判据（"判定类/参考类""指针粒度""台阶口径"） | **1** |
| 修假绿灯时造出新的假绿灯（"没输入也算过"） | **2** |
| 验收不可达成 / 不可机判 / 与文档其他部分打架 | **3** |
| 依赖关系与顺序未写；把"耦合"写成了"顺序" | **4** |
| "在哪一步失败"未定义；失败点会留半成品 | **5** |
| 缺"改完怎么验没坏"，或给的是无法证伪的自我声明 | **6** |
| 检查项误报；**豁免没留痕**；没说这是半自动 | **7** |
| 要求"多处各写同一段" → 自我制造副本；**分发副本无"裁掉了什么"声明** | **8** |
| 引用未经验证的"复核新值" | **9** |
| 分发的规范无单一源头；**只教"改全"没教"按值搜"** | **10** |
| **验收线"能算出来"就永远能过**；关键数据全缺失仍算通过 | **11** |
| **没写"谁在什么时候采集"**；口径混用；细分行与合计对不上；**规则奖励了反行为** | **12** |

> **为什么这十二条值得信**：它们是**实际发生过的失手**，不是设想中的失手。
> 但来源仍然有限（一轮改造、三个项目）——**还没到"再改也改不动"的程度**，
> 判据见 `§6 元规则` 的**终点判据**。
